# Glass3 音视频方案发布验收清单

本清单用于每次对客户交付前复核。自动化通过不替代 Glass3 真机体验，真机短测也不替代 30 分钟稳定性验收。

## 一、自动验证

- [ ] 在项目根目录执行 `./scripts/verify-all.sh`，退出码为 0。
- [ ] Android 四个模块单元测试、lint、debug/release 构建全部成功。
- [ ] 浏览器接收端完整测试通过（包括重连、替换接收端和首帧判定）。
- [ ] 两个独立源码接入应用及四个 Kotlin/Java 文档 Activity 编译成功，只取流应用没有 WebRTC 依赖。
- [ ] `git diff --check` 无空白错误。

## 二、安装与首次权限

- [ ] `adb devices` 只有一台 Glass3 且状态为 `device`。
- [ ] 执行 `./scripts/install-glass-stream-sender.sh` 安装并启动成功。
- [ ] 首次安装会请求相机和录音权限；拒绝时显示 `PERMISSION_REQUIRED`，授权后可恢复。
- [ ] 首页能分别进入“音视频传输”和“原始媒体采集”。

## 三、原始 NV21/PCM

- [ ] 不启动 PC 服务和 WebRTC，也能单独获取真实 NV21 和 PCM。
- [ ] NV21 页面显示实际宽高、FPS、帧数和字节数持续增长。
- [ ] PCM 页面显示采样率、声道、位深、音量和字节数持续增长。
- [ ] 保存一张 JPEG，可正常打开且内容来自眼镜实时相机。
- [ ] 录制一段 WAV，可在眼镜播放并听到真实环境声音。
- [ ] 扫码或其他相机应用占用时返回 `CAMERA_IN_USE`，释放后可重新开始。
- [ ] SDK 无连接回调时能明确超时，停止清理不阻塞页面；停止后可回到空闲并再次开始。
- [ ] 在采集回调中停止/退出不会卡死，停止或冷却等待期间取消后不自动恢复采集。

## 四、浏览器传输

- [ ] 浏览器先启动、眼镜后启动时，音频加视频正常。
- [ ] 眼镜先启动、浏览器后启动时，能从等待状态进入推流。
- [ ] 视频单独启用正常，音频单独启用正常。
- [ ] 浏览器点击“开启声音”后音频连续，无异常回音或眼镜侧播放链路启动。
- [ ] 关闭并重新打开浏览器接收后，眼镜可以恢复连接。
- [ ] 协商完成但无首帧时显示等待；纯音频不误报有视频，数据中断后不继续显示正常接收。
- [ ] 区分实际采集与编码尺寸，尝试不同视频选项后记录实际首帧和持续输出，不只记录请求参数。
- [ ] Wi-Fi 断开后按 1、2、4 秒有限退避重连；恢复网络后可继续。
- [ ] 连续停止和开始 10 次，每次均能重新获得相机和麦克风。
- [ ] 切换前后台、返回首页和直接退出页面后，采集与网络资源全部释放。

## 五、30 分钟稳定性

- [ ] 记录开始和结束时间、实际分辨率/FPS、音视频码率、丢帧、PCM 欠载/溢出和 RTT。
- [ ] 在第 0、10、20、30 分钟记录进程内存，并观察设备温度。
- [ ] 没有 `SIGABRT`、`FATAL EXCEPTION`、音频服务崩溃或无法恢复的 Binder 断开。
- [ ] 没有 CameraShare 泄漏、退出后后台采集、无界内存增长或停止后无法再次启动。
- [ ] 真实记录保存在 `docs/acceptance-results/`，失败项保留原始证据，不预填通过。

## 六、客户交付包

- [ ] 执行 `./scripts/build-customer-release.sh` 成功。
- [ ] `dist/glass3-media-streaming-1.0.0/` 包含 debug APK、未签名 release APK、Android 源码组件、接收端、接入验证工程、脚本、完整页面及其共用队列、文档和 `SHA256SUMS`。
- [ ] 包内没有 `node_modules`、Gradle 缓存、构建中间目录、签名文件、密钥、口令和固定客户内网地址。
- [ ] 在交付目录执行 `shasum -a 256 -c SHA256SUMS` 全部通过。
- [ ] 未签名 release APK 已明确由客户使用自己的签名流程签名。

## 七、版本控制

- [ ] 验收证据不含账号、令牌、客户隐私或不必要的设备唯一标识。
- [ ] `git status --short` 为空；生成的 `dist/` 已忽略。
- [ ] 未经单独授权，不创建 tag、不推送远端、不发布外部下载。
